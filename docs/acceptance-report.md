# Development acceptance report

This report records evidence available in the local development environment. It is intentionally not a production-release sign-off: Linux/production FRP deployment matrix, Cloudflare Sandbox, ACME Staging, production TLS termination, formal security scanners and signing still require their external environments.

## Verified locally

- Separate Server and Client Go modules compile and test independently.
- `make build` and the Docker build stages embed the matching Admin/Client static assets into the corresponding Go binary; external `FRP_*_WEB_DIR` paths are explicit overrides only.
- Two independent Vue 3 + TypeScript + Vite + Element Plus apps build successfully.
- Admin login does not render a Server address field; Client login does not render admin or device-registration fields.
- Client Panel exposes separate Mapping and Domain Binding surfaces; the Domain Binding view shows normalized IDNA names and keeps `pending_dns` visibly distinct from `active`.
- Frontend policy tests cover the Admin first-login credential gate/destructive-action re-auth boundary and Client status/dangerous-operation guards at 100% line/branch/function coverage for the policy modules.
- Argon2id password hashing, first-login password change and user creation work.
- Second Client login returns `SESSION_REPLACED` for the old opaque session.
- TCP Mapping auto-allocation reserves port `6000`; TCP/UDP conflict returns upstream HTTP 409.
- Desired/applied config versions converge after Client verifies the signed snapshot and applies through Supervisor.
- HTTP Mapping and IDNA/Punycode Domain Binding creation produce explicit `pending_dns` states.
- SQLite WAL encrypted backup endpoint generated an `.fppb` package in a temporary test data directory.
- FPPB1 decode, password rejection, SQLite integrity validation, and atomic restore with a recoverable pre-restore filename pass unit tests.
- Cloudflare HTTP Provider unit tests cover bearer auth, zone-record discovery, create, update, and delete without requiring a live network.
- Domain creation persists and validates A/AAAA/CNAME intent, TTL and HTTPS-derived `proxied` state before the DNS job; the Client Domain surface displays the effective record values.
- Durable Job Worker tests cover deduplication, lease heartbeat, expired-lease reclaim, retry backoff, Cloudflare token verification, DNS conflict handling and Router snapshot promotion.
- Mapping updates enforce `expected_revision` and persist PUT idempotency records; long-running jobs renew their leases, Cloudflare 401/403 errors are classified as permission failures, and ACME renewal/deletion jobs are re-seeded after restart.
- Domain deletion removes the Router route after the Client acknowledgement and only deletes Cloudflare DNS when `managed_by_panel=true`; adopted unmanaged records remain external.
- Router tests cover HMAC/hash rejection, last-good retention, control/business Host routing, unknown Host 404 and offline upstream 502. Router runtime has no database dependency.
- ACME DNS-01 provider is implemented with the Go ACME client, encrypted account material, TXT propagation polling and cleanup; it remains disabled unless an operator supplies a staging/production directory, email and verified Cloudflare Token.
- FRPS fixed-binary process tests cover SHA-256 verification, PID ownership, proxy-only reload in place, last-good rollback restart, orphan recovery and controlled stop.
- An opt-in test starts fixed official FRP v0.68.0 FRPS and FRPC with a real loopback Server Plugin, creates a real Server Session/Mapping metadata set, and proves Login/NewProxy/WorkConn/NewUserConn plus the proxied TCP payload; the ordinary protocol test covers Ping/CloseProxy rejection paths.
- Server/Client WebSocket tests cover the v1 envelope boundary, heartbeat session renewal, remote disable cleanup, bounded exponential backoff with jitter, and signed full-sync recovery after configuration notifications.
- Pending quotas cover mappings, pending port leases, domain operations and certificate jobs; metrics expose resource counts, job backlog, Router lag and SQLite WAL size without user-input labels.
- Mapping deletion retains domain bindings until managed DNS cleanup succeeds; a focused service test proves managed records are deleted and mapping operations only finalize after compensation. Port rotation proves the old lease is released only after the new revision applies.
- Revision failure rollback is transactional: the pending revision is retained as `failed`, `pending_revision_id` is cleared, the previous active revision and port remain authoritative, and a replacement port lease is released. A follow-up update can create the next immutable revision.
- Administrator user deletion enters a durable `deleting` state, revokes sessions/runtime credentials immediately, shuts down the Client path, cleans Domain/Mapping resources in dependency order, retains the user operation after local row removal, and records unresolved external DNS residue when forced cleanup is requested. The admin Operation API and UI expose each residue's provider, identifier and reason, with a separate audit event.
- Client startup writes an ownership PID marker for fixed-binary FRPC and recovers an orphan only after matching the configured binary command line; recovery removes runtime configuration/secrets and refuses PID-reuse termination.
- Server admin cookie writes require a session-bound CSRF token; Cloudflare token changes, FRP credential rotation, user lifecycle changes, Router rebuild and encrypted backup require a short-lived reauthentication ticket. Client LAN exposure requires an explicit non-loopback bind, CIDR/Host allowlist and TLS certificate/key, and service-to-service HTTP clients reject redirects.
- Versioned master/certificate key rings retain old keys during migration. The `make key-rotate` maintenance path re-wraps FRP credentials, Cloudflare Tokens and certificate private keys in a SQLite transaction; crypto restart compatibility and service row-count/re-login tests pass. A real production rotation window remains unsigned-off external work.
- Before Client login, the Server certificate is inspected without sending the password. HTTPS connections require normal certificate validation or an explicit operator-confirmed SPKI pin; the pin is memory-only, bound to the selected Server, and a wrong pin fails before an HTTP handler is reached. IP endpoints therefore cannot silently bypass certificate trust.
- Client Server switching logs out the old Server, stops the old FRPC path, clears runtime secrets and cache, and starts one new Client Session. Offline fallback is limited to GET snapshots for the current session; session replacement/disable and all 4xx responses invalidate or surface the error instead of serving stale cache. Browser `localStorage` contains only `last_server_panel_url`; CSRF and runtime secrets remain in memory.
- Mapping toggle, Domain deletion and DNS conflict actions persist request hashes under the authenticated session generation; retries return the original outcome and conflicting bodies return `IDEMPOTENCY_KEY_REUSED`. Toggle also enforces optional expected config/revision values.
- All authenticated Server write routes require `Idempotency-Key`. Resource transactions retain their typed idempotency records and the remaining write routes use a shared encrypted-response replay layer; same-key/different-body conflicts return 409, while replayed responses receive the current request ID. Unsupported non-empty protocol versions return RFC-style `426 UPGRADE_REQUIRED`.
- Client/Server version compatibility is enforced before Client Session creation: `X-FRP-Client-Version` is validated, old/invalid Clients receive `426 CLIENT_VERSION_UNSUPPORTED` plus `Upgrade-Required` metadata, and supported but older Clients receive a visible upgrade suggestion without a parsing failure.
- `http_only` is enforced as a fixed no-certificate/no-redirect mode in the API, service layer, Client form and SQLite CHECK/trigger migration, preventing contradictory TLS configuration from reaching a DNS or Router job.
- Client Operations exposes phase, step, status, error, retry and external-residue information, giving long-running asynchronous work an explicit loading/error/retry surface.
- Formal FPPB1 backup tests include protected data-directory files, per-entry checksums, wrong-password rejection, SQLite integrity validation, session/runtime credential revocation and atomic restore.
- `scripts/validate-openapi.rb` validates both OpenAPI 3.1 contracts, unique operation IDs, WebSocket metadata and independent implementation route parity: Server 34 paths / 39 operations and Client Local API 20 paths / 23 operations. `make sbom` emits a local SPDX inventory, `make checksums` emits SHA-256 checksums for panel and fixed FRP artifacts, and the release manifest records FRP v0.68.0 hashes. Artifact signing and third-party scanner attestations remain release work.
- The implementation-level response contract test, previous-stable migration rehearsal, Vue ESLint gate, npm license allowlist, independent panel version metadata, and Router header/body/upstream timeout boundaries are now run by `make contract`, `make migration-check`, `make lint`, `make license`, and CI.
- `openapi-typescript` generates `contracts/generated/server-api.d.ts` and `contracts/generated/client-api.d.ts`; both panel request layers are typed against their corresponding generated OpenAPI paths, both model layers consume generated schema types, and CI fails when regeneration changes either committed contract artifact.
- Coverage gate: Server Go line coverage is 75.1%; Client Go line coverage is 76.0%. Authentication (94.7%), token encryption (91.4%), Router runtime/snapshot (92.1%) and the targeted Session/port-lease failure paths meet or exceed the documented critical-module threshold; the lifecycle tests cover successful Revision switching and port rotation.
- Final local regression: Server and Client `go test -race ./...`, `make lint`, `make build`, `make contract`, `make security`, 2-second fuzz targets, the PERF-001~007 local profile, fixed FRPC/FRPS v0.68.0 `verify`, checksum validation, native FRPS/FRPC TCP network E2E and the opt-in real FRPS/FRPC + Plugin metadata E2E all pass. PERF-003/005/007 are measured on the current development host and still require the documented Linux/production target-scale matrix. The release build emits only `frp-panel-server` and `frp-panel-client`; the backup restore command remains a Server source-level operational tool. Vite reports a non-blocking warning for the current JavaScript chunk size. Docker image build/scan was not locally executable because the current Docker daemon was unavailable, so it remains an external CI/release gate.
